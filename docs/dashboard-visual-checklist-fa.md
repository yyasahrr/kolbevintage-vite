# چک‌لیست بررسی بصری داشبورد

این چک‌لیست هنوز اجرا نشده است؛ محیط فعلی Chromium ندارد (`npm run goldens`: `goldens: no browser found`). پیش‌نمایش split-screen به‌تنهایی اثبات اندازه viewport نیست. در مرورگر واقعی با DevTools و viewport دقیق ۳۲۰، ۳۹۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰ و ۱۴۴۰، در هر دو تم و با داده خالی و پر:

- [ ] screenshot قبل/بعد، ارتفاع کارت‌ها، گرید ۱۲ ستونی، عرض سایدبار و خوانایی را بررسی کنید.
- [ ] عدم اسکرول افقی صفحه، نام‌های طولانی، بزرگنمایی ۲۰۰٪، محتوای جدول و اسکرول افقی داخلی آن را بررسی کنید.
- [ ] باز/بسته‌کردن drawer با دکمه، overlay و Escape، trap و بازگشت focus و تغییر عرض حین باز بودن را بررسی کنید.
- [ ] جمع/بازکردن سایدبار، آیکون‌های بدون برچسب، نام قابل‌دسترس و تمام مقاصد مجاز را بررسی کنید.
- [ ] جست‌وجوی بخش‌ها با کلیک و Ctrl+K، اعلان، وضعیت اتصال، تم و خروج را با ماوس و کیبورد بررسی کنید.
- [ ] تغییر بازه، وضعیت‌های loading/error/403/empty/zero و مرتب‌سازی سفارش‌ها را با API و نقش‌های متفاوت بررسی کنید.
- [ ] رنگ‌ها، اندازه لمس، focus، خوانایی نمودار وضعیت و اعلام وضعیت‌ها با صفحه‌خوان بررسی شود؛ axe و تست دستی جایگزین هم نیستند.

آزمون‌های stylesheet موجود عمدتاً `admin.css` را بررسی می‌کنند؛ `admin-shell.css` و `dashboard.css` در خروجی responsive/contrast آن‌ها پوشش کامل ندارند. از تأیید تولیدی یا نتیجه بصری پیش از اجرای این فهرست خودداری کنید.
