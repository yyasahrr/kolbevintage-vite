# فهرست سفارش: قرارداد و محدودیت‌ها

فهرست از `GET /api/admin/orders-list` و پیش‌نمایش از `GET /api/admin/orders-list/:id` خوانده می‌شود؛ هر دو در سرور `orders:view` می‌خواهند. APIهای قبلی دست‌نخورده‌اند. خروجی فهرست و پیش‌نمایش ایمیل، تلفن، نشانی و سند خام را برنمی‌گرداند. این دو API فقط خواندنی‌اند؛ selection هیچ mutation یا export انجام نمی‌دهد. مسیر قدیمی جزئیات سفارش و APIهای قدیمی در این patch تغییر نکرده‌اند و باید جداگانه از نظر RBAC بازبینی شوند.

فیلترها روی رکوردهای `orders` و وضعیت‌های موجود هستند؛ تاریخ‌ها روز میلادی و مطابق timezone جلسه PostgreSQL، پایان بازه شامل روز انتخاب‌شده است. جست‌وجو بر شناسه و نام مشتری و pagination سرور ۲۵تایی است؛ sort مبلغ عدد ذخیره‌شده را بدون تبدیل ارز مقایسه می‌کند. مبالغ با ارز ذخیره‌شده نمایش داده می‌شوند؛ تبدیل به تومان بدون نرخ و قرارداد معتبر ممنوع است. اقلام از `order_lines` می‌آیند؛ برای سفارش‌های قدیمی فاقد snapshot، تعداد و اقلام نامشخص‌اند، نه صفر. چند query صفحه و count snapshot مشترک ندارند. منبع سفارش، نشانی، رویدادها و دسته مرجوع‌شده از قرارداد حاضر مشخص نیستند و جعل نمی‌شوند.

سفارش دستی، صادرات، چاپ، انتقال وضعیت گروهی، فیلتر مرجوعی و تاریخچه در این مرحله عرضه نشده‌اند. صفحه جزئیات کامل قدیمی بازنویسی نشده و از پیش‌نمایش به آن لینک داده نشده تا داده ناقص را کامل جلوه ندهیم. پیش‌نمایش در محیط فعلی دارای seed و برچسب آزمایشی است و سفارش نمونه در دیتابیس تولید ایجاد نمی‌کند. جست‌وجوی سراسری تنها بخش‌های پنل را جست‌وجو می‌کند؛ Ctrl/Cmd+K عمداً در فیلدهای ورودی فعال نیست. اعلان‌ها شمارش‌های عملیاتی فعلی‌اند، نه رویدادهای خوانده‌نشده یا بلادرنگ.

پیش از انتشار، بررسی دسترسی تمامی APIهای قدیمی سفارش، timezone، نرخ و واحد پول، snapshot خط سفارش، test مرورگر و کنتراست و تعامل در عرض‌های ۳۲۰، ۳۹۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰ لازم است. ابزارهای استاتیک استایل مخزن فایل‌های جدید CSS را کامل بررسی نمی‌کنند.
